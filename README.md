# Проект — Telegram Bot

Минимальный Telegram-бот проекта «Проект».

## MVP

- `/start` — приветствие и основное действие;
- `/help` — краткая помощь;
- `/status` — проверка работы бота;
- кнопка `Подтвердить номер`;
- запрос собственного контакта пользователя через Telegram `request_contact`;
- проверка, что переданный контакт принадлежит отправителю;
- нормализация номера телефона;
- подтверждение номера пользователю.

## Требования

- Node.js 20+;
- Telegram Bot Token от BotFather.

## Локальный запуск

```bash
npm install
cp .env.example .env
```

Добавьте токен в `.env`:

```env
TELEGRAM_BOT_TOKEN=your_token_here
```

Запуск:

```bash
npm start
```

Для разработки:

```bash
npm run dev
```

## Безопасность

Токен Telegram никогда не должен попадать в Git. `.env` исключён через `.gitignore`.

Номер считается подтверждённым только если пользователь передал свой контакт через Telegram-кнопку `request_contact`. Номер, написанный обычным сообщением, подтверждением не считается.

Текущий MVP специально не содержит базы данных и интеграции с сайтом, чтобы сначала получить простой рабочий бот и проверить его в Telegram.

## Подтверждение Owner для M POS

`src/owner.js` подключён к существующему Telegraf-процессу. Второй poller/webhook не создаётся. Обычный `/start` с токеном checkout продолжает прежнюю обработку; Owner-ссылки имеют отдельный префикс `owner_`.

Дополнительные переменные:
- `OWNER_API_URL`: HTTPS URL backend M POS (по умолчанию используется существующий `VERIFICATION_API_URL`).
- `OWNER_BOT_SHARED_SECRET`: отдельный случайный секрет, совпадающий с backend.

`/myid` в личном чате показывает собственный числовой Telegram ID для контролируемой первичной настройки. Владельцем становится только заранее разрешённый backend пользователь на заранее проверенном iPad. Отправка ссылки другому пользователю или в группу не даёт права подтверждения. PIN бот не запрашивает и не принимает.

Перед включением перевыпустить прежний токен бота, который был сохранён в старом POS, и обновить секреты существующего бота и backend совместно. Рабочие отчёты после обновления отправляет backend. Не менять бота и не запускать второй экземпляр long polling.

Проверка без реальных сообщений: `node --test tests/owner.test.mjs`. Живую привязку, восстановление PIN, отчёт смены и checkout нужно проверить отдельно после настройки backend и обновления iPad.

При включённом Owner backend требует shared secret также для прежнего подтверждения телефона checkout. Обновлённый `src/index.js` передаёт его; сначала обновить бот и его окружение, затем включать `OWNER_AUTH_ENABLED`.

## Кнопка владельца: текущая информация POS

Если Telegram ID пользователя сохранён на iPad в поле «ID владельца», обычный `/start` показывает ему кнопку **«📊 Получить информацию»**. Бот передаёт backend ID из проверенного личного Telegram-контекста. Backend запрашивает открытый POS и возвращает выручку текущей смены, наличные, карту, количество чеков, категории и позиции.

Продажи бот и backend не сохраняют. Если POS закрыт, потерял интернет или не ответил вовремя, владелец получает сообщение `POS не активен`. Если POS отвечает, но смена закрыта, бот отдельно сообщает, что POS онлайн и открытой смены нет.

Используются существующие `OWNER_API_URL` и `OWNER_BOT_SHARED_SECRET`; второй экземпляр бота, webhook или polling не создаются. Проверка: `npm test`.
